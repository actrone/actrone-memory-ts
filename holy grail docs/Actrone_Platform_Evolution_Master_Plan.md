## 0. The unifying idea

Actrone has three things that must become *one coherent system*:

1. **Three ways to build agents** — native Actrone SDK, BYOF (Actrone SDK + LangGraph/CrewAI/…), and EMAOP no-code. Today the Control Tower blurs them ("New agent" wrongly opens Agent Studio). They need clear separation, their own walkthroughs, and a consolidated overview.
2. **An entitlements-driven surface** — what an org *paid for* + what it *chose to enable* should decide what onboarding asks and what the Control Tower shows. The `FeatureGate`/entitlements layer already shipped is the seam for this.
3. **A premium, governed experience** — a best-in-class chat interface, real integrations with official branding and OAuth, scoped RBAC per feature, and infrastructure (mesh, gateway, environments) that scales and feels enterprise.

The throughline: **clarity + entitlements + premium polish, all reusing the seams already built.**

## 2. Control Tower UX fixes (smaller, high-impact)

These are concrete, mostly-frontend fixes that don't need their own doc.

### 2.1 OrgBar: always pinned + visible
**Problem:** the OrgBar scrolls with the nav because the whole `<aside>` is `overflow-y-auto`.
**Fix:** restructure the sidebar as a flex column — `nav` becomes `flex-1 overflow-y-auto` (the only scroll area), `OrgBar` sits *outside* it as `shrink-0`, so it's permanently pinned at the bottom regardless of scroll. Same treatment in the mobile drawer. (`components/layout/Sidebar.tsx`.)

### 2.2 OrgBar theme submenu not opening
**Problem:** the theme Radix `DropdownMenuSub` doesn't expand its light/dark/system options.
**Likely causes to investigate:** (a) the sub-content is rendering but mis-positioned/clipped by the sidebar's `overflow`/`z-index`; (b) the submenu needs the portal to escape the sidebar stacking context; (c) `DropdownMenuSubContent` missing a portal wrapper.
**Fix direction:** ensure `DropdownMenuSubContent` is portalled (Radix portals by default via `DropdownMenuPortal` — verify our primitive wraps it), raise z-index above the sidebar, and confirm the sub opens on hover *and* click. Alternatively promote Theme to a top-level inline radio group in the ⋯ menu (3 items) — simpler and removes the submenu failure mode entirely. **Recommendation: flatten theme to inline radio items** (Light / Dark / System) in the ⋯ menu.

### 2.3 Sidebar branding → org logo
**Today:** brandmark + "Control Tower" text.
**Plan:** default to the **full Actrone logo** (wordmark) in the sidebar header. Orgs/users can **upload an organization logo** (Settings → Organization → Branding) that replaces it across the sidebar header + OrgBar avatar fallback. Source of truth: Clerk org `imageUrl` (already settable) for the avatar, plus a dedicated `branding.logo_url` in org metadata for the wide sidebar logo (light + dark variants). Fallback chain: org logo → Actrone wordmark. Respect theme (logo has light/dark asset).

### 2.4 API key generation + copy — two surfaces
- **Quick action (top bar):** a "API key" button in the new top-right cluster (next to the environment switcher) for fast generate/copy — but **never display a full key after creation** (show once, then masked). Keys are **per-environment** (see §2.5 + infra doc).
- **Full management page:** Settings → API Keys — list (masked), create (named, scoped, env-bound), reveal-once, revoke, last-used, rotation reminders. The backend `repository.APIKeyRepository` + `/v1/auth/api-keys` already exist; this is mostly a frontend page + per-env scoping.

### 2.5 Environment switcher (dev / staging / prod)
A segmented switcher in the **top-right** of the Control Tower. Selecting an environment scopes every view (agents, tasks, keys, connectors, governance) to that environment. This is both a UX and a data-model change — see [Infrastructure & Environments](./Actrone_Infrastructure_and_Environments_Plan.md) §3. Visually: a small pill (`Production` in brand-red, `Staging` amber, `Development` neutral) — instantly communicates "you are operating on prod" (premium + safe).

### 2.6 New top-right cluster
Introduce a consistent top-right header cluster on every Control Tower page: **[ Environment switcher ] [ API key ] [ Mode/Help ]**. Pairs with the existing OrgBar (bottom-left identity) for a balanced, Vercel-grade chrome.

## 4. Principles carried throughout
