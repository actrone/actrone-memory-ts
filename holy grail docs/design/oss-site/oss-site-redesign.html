Actrone /oss launch mode /site and docs redesign /direction 01

design direction · 2026-09-05

Stop describing the memory. Show it.

In OSS launch mode, actrone.com is one thing: the front door to a free memory library for AI agents. Everything a visitor needs to judge it is concrete, and none of it is currently on screen. They see a hero, a bento grid of capability cards, and a waitlist form. They never see a memory.

This redesign turns the site into the thing it is selling: an inspectable ledger. The hero is a real memory table with real sensitivity tags. The page then walks the actual lifecycle of a fact, store, classify, recall, budget, and each step is drawn, not claimed. The brand does not move: Black and Apple Silver, Geist, 1px borders, status-only chroma, all locked and all honoured. What changes is the craft, the typography, and the information design.

01

What is wrong today

Not the palette. The palette is right and it is locked. The problem is that the OSS home is the platform home with three sections left in, and that the type, spacing and structure are doing no work at all.

  • rhythm Three sections, all generic. OssHome renders a hero, a capability bento and a waitlist. A visitor evaluating a memory library gets adjectives (hybrid, budget-aware, PII-aware) and never one row of memory. The mechanism is the product, and the mechanism is absent.
  • typography Geist at default settings is not a type system. Display type sits at text-7xl with Tailwind’s default tracking, so a 72px headline reads soft and wide. There is no measure discipline on body copy, no tabular figures on data, and mono is used decoratively rather than structurally.
  • surfaces Everything is a card. Nearly every block on the page is rounded-lg border p-6 on --color-surface. When each element gets the same border, radius and fill, hierarchy flattens and nothing can be emphasised. The brand says depth comes from 1px rules; the site uses rules to draw boxes instead of structure.
  • proof The proof strip is a slogan strip. OSS_HERO_PROOF prints “RRF” and “0 API keys” as four large values. Both are true and neither is shown. A developer cannot verify a claim rendered as a number in a grid.
  • docs The docs index is a link farm. Six pages survive OSS mode, and the entry point presents them as a card grid with a start-here section, which is the shape you use for forty pages. At six, the docs should open into content.
  • honesty The best asset is buried in the README. Both memory repos carry a candid section on exactly where PII protection holds and where it does not. That candour is a stated brand trait and a differentiator in a category full of overclaim. It should be on the homepage.

01

Store a turn. That is the whole setup.

MemoryManager.create() with no arguments gives you an in-process store and a dependency-free embedder. No Redis, no Qdrant, no OpenAI key. Swap any of the three later by passing an adapter; the manager and your calling code do not change.

quickstart.ts 
import { MemoryManager } from "actrone-memory";

// In-memory store plus a local embedder. Nothing to run, nothing to configure.
const mm = await MemoryManager.create();

await mm.storeTurn(
  "support-bot", "sess-1",
  "I'm Alex, I'm building a trading bot.",
  "Nice to meet you. Which asset class?",
);

// A durable fact, written straight to long-term memory.
await mm.injectMemory("support-bot", "Works at Northwind Capital", 0.9);
import asyncio
from actrone_memory import MemoryManager

async def main():
    # In-memory store plus a local embedder. Nothing to run, nothing to configure.
    async with MemoryManager.create() as memory:
        await memory.store_turn(
            agent_id="support-bot", session_id="sess-1",
            user_message="I'm Alex, I'm building a trading bot.",
            assistant_message="Nice to meet you. Which asset class?",
        )

        # A durable fact, written straight to long-term memory.
        await memory.inject_memory("support-bot", "Works at Northwind Capital", 0.9)

asyncio.run(main())
02

Every fact carries its sensitivity

Extraction pulls durable facts out of a turn and tags each one none, low, pii or sensitive. The tag travels with the memory, so you can redact, filter or audit on it. This is memory that is governance-adjacent by construction, which is the thing a black-box memory store cannot give you.

  • none

    Ordinary preferences and project facts. Stored plainly, always recallable.

  • low

    Identifying but not private. Employer, city, role. Filterable at recall.

  • pii

    Personal data. Email, phone, address. Maskable in place at recall.

  • sensitive

    Financial, health, credentials. Masked with pii, and worth a policy.

03

Recall is fused, not guessed

Pure vector search returns things that sound related. Actrone runs a dense search and a lexical search, weights recency, then fuses the three ranked lists with reciprocal rank fusion. An item that places well on two signals beats an item that wins one. Reranking is optional on top.

04

Context that fits, every time

You pass a token budget. The manager fetches turns and memories in parallel, allocates the budget across them, ranks, then prunes to fit. You never get back a context object that blows your window, and you never write the trimming logic yourself.

06

What this does not do

Every memory library’s landing page lists what it does. Here is the other half, on the homepage rather than three clicks into a README, because you will find it out on day two anyway and we would rather you trust the first list.

  • PII tagging is not PII protection on a cloud model

    The pii and sensitive tags are produced by the extraction step, and that step sees the raw text. With the defaults, extraction and embedding run in-process, so nothing leaves your machine and the protection is real. Point either at a cloud provider and the raw text, including everything tagged pii, is sent to that provider. This library does not tokenise before inference. The hosted platform does.

  • It stores and recalls. It does not build a knowledge graph

    Turns and extracted facts, retrieved well. It does not do the entity consolidation or temporal graph reasoning some alternatives do. If your problem is “my agent forgets”, this fits. If your problem is “resolve conflicting facts about an entity over time”, it does not, yet.

  • We publish our own eval, not a head-to-head

    The library ships a quality eval that runs offline in one command and is gated in CI at recall@5 >= 0.85. It currently scores 0.929. Two things that number is not. It is not a public-dataset result: the bundled set is LongMemEval-style, not LongMemEval itself. And it is not a comparison: we have never run Mem0 or Zep through the harness, so there are no head-to-head figures here, and there will not be until we have run them. The zero-dependency default embedder is keyword overlap, so paraphrases score low.

  • The two languages are at parity in the core, not in the adapters

    MemoryManager behaves identically in both. The framework integrations do not: Python ships deep adapters as optional extras, and TypeScript ships structural helpers. If you need a specific framework adapter, check the integrations page before you commit.

memory / overview

Two-tier memory

A memory manager keeps two stores. L1 holds the recent turns of the current session and is read by recency. L2 holds durable facts and is searched semantically. One call reads both and returns a context that fits your budget.

installshell
npm install actrone-memory
pip install actrone-memory

How a turn becomes memory

storeTurn appends the user and assistant messages to L1. If extraction is enabled, durable facts are pulled out of the turn, classified, and written to L2. Session turns expire; L2 facts do not.

  • L1Session turns. Recency-ordered, token-bounded, cleared by clearSession. In-memory by default, Redis in production.
  • L2Episodic memories. Embedded and searchable, each carrying an importance score and a sensitivity tag. In-memory by default, Qdrant in production.

note

The defaults need no services. MemoryManager.create() with no arguments gives you an in-process store and a dependency-free embedder, which is also what makes the test suite run fully offline.

retrieveContext

Four phases, in order: fetch turns and search L2 in parallel, allocate the token budget across both, rank by fused score, prune to fit.

parametertypedescription
agentIdstringrequiredNamespace for the memory. Two agents never see each other’s L2.
sessionIdstringrequiredWhich session’s L1 turns to read. L2 is not scoped by session.
querystringrequiredWhat the agent is about to answer. Embedded and term-matched against L2.
tokenBudgetnumberrequiredCeiling for the assembled context. The result is guaranteed to fit.

where PII protection holds

Sensitivity classification happens during extraction, and extraction sees the raw text. With local models nothing leaves the machine. Point extraction or embeddings at a cloud provider and the raw text is sent there, tags included.

Where I would like your call

The direction above is one coherent position. These four are the places where a different answer changes the build, so tell me and I will fold it into the next pass.

  1. 01The hero. A ledger of real memories instead of a code panel. It is the single biggest departure from the current page and everything else follows from it.
  2. 02The honesty section on the homepage. Four things the library does not do, given the same typographic weight as the features. Defensible and unusual. Also the easiest thing to lose your nerve on.
  3. 03The headline. “Your agent’s memory, written down.” replaces “Memory your agents don’t forget.” The accent face carries “written down.”
  4. 04Docs root is the entry point. Redirect /docs into the overview. Rejected by the owner, 2026-09-09. /docs renders its own index in every launch mode; the Home tab stays in the docs header.
