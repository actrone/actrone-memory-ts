01

What exists today

Both routes are built, tested and in the full sitemap. None of it reaches an OSS visitor, and what would reach them is not ready.

Built but hidden
OSS_HIDDEN_PREFIXES in lib/flags.ts redirects /blog and /changelog to the homepage. Neither is in the OSS nav, the OSS footer, the SEO registry or the sitemap.
Changelog is hand-typed
changelog/page.tsx copies releases into a RELEASES array. It stops at TypeScript 0.1.0 and Python 0.2.0, so 0.1.1, 0.1.2 and 0.2.1 are missing and create-actrone-app is not listed. Its own comment names the CHANGELOG.md files as the source of truth; nothing checks it.
Blog renderer splits strings
Posts are template strings in lib/blog/posts.ts, split on blank lines. A bold line becomes a heading, links are raw HTML through dangerouslySetInnerHTML, and there are no code blocks, tables, images or heading anchors.
Copy that is no longer true
Two of the three posts make claims the current library, or the hosted platform that has not launched, cannot back up. Part 02 lists each one.
Brand drift
tracking-widest eyebrows, a box shadow on the category tabs, ← text glyphs instead of lucide icons, an em dash in a code comment, accent-tinted category pills, and page metadata written by hand outside the SEO registry, so neither page gets a registry date or a standard OG card.
Wrong byline
Every post credits “Matt Nyirendah, Founder”. The correct byline is Matthew Nyirenda, Founder and CEO, Apocalypse Technologies, and the JSON-LD names an Organization as the author where it should name the person.
No feeds
Developers follow releases and engineering posts through RSS and GitHub. Neither page offers a feed today.

How we designed two-tier agent memory: Redis + Qdrant

Rewrite

Describes an earlier design. Five of its specific claims contradict today’s library or its docs, and two of its numbers cannot be traced to any run.

ClaimVerdictEvidenceFix
“Layer 1 is Redis. Layer 2 is Qdrant.”OutdatedThe default is the in-memory store; Redis, Valkey or Postgres back L1, Qdrant or pgvector back L2Describe the default, then the options
“Every turn is embedded and stored as a vector”WrongTurns stay in L1. L2 holds injected facts, Python’s session summaries and extracted facts (docs, memory overview)Correct it
“Ranked by a combined score of 0.7 × relevance + 0.3 × recency”OutdatedThe default is Reciprocal Rank Fusion of dense, BM25 and recency; the weighted blend is the fallback with hybrid retrieval off (docs, retrieval)Correct it
“0.72 emerged from empirical testing across 50,000 retrieval queries”UnverifiableNo such run exists in either repo; thresholds are now calibrated per embedder (0.3 keyword, 0.63 bge-small)Remove; explain per-embedder calibration
“If a slot is under-utilised, the remainder is redistributed proportionally”WrongAn unused budget share is not handed to the others (docs and code)Correct it
“Compresses the session using GPT-4o-mini”IncompletePython only; GPT-4o-mini only with the OpenAI provider, an extractive summary otherwise; TypeScript does not summariseCorrect it
“In production: Redis L1 P99 < 1ms ... at 100 concurrent agents: < 5% latency regression”UnverifiableThere is no production deploymentUse the benchmark’s figures (p50 0.22 ms, p95 0.61 ms, in-memory, keyword embedder) with the command to rerun them

actrone-memory ships adapters for 16 Python frameworks and 11 TypeScript ones. Until this release, we checked that glue against each framework’s types and against stub models. That catches a renamed parameter. It cannot tell you whether the memory ever reaches the model.

Checking the code against the real frameworks#

Each library’s public Framework Compatibility workflow installs every framework at the oldest and the newest release its supported range allows, then drives the adapter through the real framework.

Checking the result against a real model#

  1. Store one fact a model cannot guess: the payments team’s escalation codeword is PELICAN-42.
  2. Put a recording proxy between the framework and Ollama, so every request is logged.
  3. Ask for the codeword through the framework.

07

Data, build, SEO and accessibility

Where each page’s content comes from, what keeps it honest, and what search engines and screen readers get.

Posts
One Markdown file per post in apps/marketing/content/blog, with front matter: title, optional search title, description, published date, revision date, kind and notice, category, author, further reading, and audience (oss or platform). The OSS build serves only oss posts. scripts/sync-blog.mjs validates every post and compiles it into src/generated/blog-posts.json (metadata, headings, reading time) and blog-bodies.json, with a check:blog CI gate. Bodies render with react-markdown and remark-gfm, which the app already depends on; a fence written as snippet:<package>/<id> renders that tested example from generated/snippets.json (D1).
Releases
scripts/sync-changelog.mjs reads actrone-memory-py, actrone-memory-ts and create-actrone-app CHANGELOG.md (Keep a Changelog headings) into src/generated/changelog.json, the same pattern as sync-snippets. check:changelog fails CI when the committed file is stale, and prebuild runs the sync. A version marked internal in its heading renders with the Not published label.
Feeds
/blog/rss.xml and /changelog/rss.xml as RSS 2.0 route handlers, built from the same data, with no new dependency. Linked from each page header and advertised with <link rel="alternate">.
SEO
Registry entries in lib/seo/pages.ts for /blog, /changelog and each post, so the sitemap, OG cards and llms.txt pick them up. Posts get BlogPosting JSON-LD with a Person author and dateModified; the changelog gets a CollectionPage. After deploy: IndexNow for the new URLs.
Accessibility
One h1 per page and sequential headings; real time elements; the filter is a labelled button group with aria-pressed and a polite live count; disclosures use aria-expanded; heading anchors and every link have visible focus; all text uses tokens that already pass WCAG AA in both themes; motion is off under reduced motion.
Gates
brand:check and seo:smoke cover the new pages automatically through the sitemap. New tests: the OSS gate allows the routes, every OSS post has a registry entry, every post and release passes the dash and sentence-case rules, and the generated changelog matches the files.

All eight approved by the owner on 1 October 2026, with the byline in D8 corrected to the owner’s name and title.

D1

How posts are written

Posts need headings, code, tables and links that the string splitter cannot render.

ApprovedMarkdown posts with the docs’ components. Built with react-markdown and remark-gfm, which the marketing app already depends on, instead of @next/mdx: the same Markdown authoring with headings, code, tables and links, and no new packages. Found during the build; recorded here so the spec matches the code.
Not chosenTyped content blocks in TypeScript: no new dependency, but every paragraph is an object, which makes writing slow.
